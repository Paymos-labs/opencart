# Paymos для OpenCart

[English](README.md) | [简体中文](README.zh-CN.md) | **Русский** | [Español](README.es.md) | [Deutsch](README.de.md) | [Türkçe](README.tr.md)

Официальный платёжный модуль Paymos для OpenCart 4.0.2.0 и новее. Покупатель подтверждает заказ, попадает на страницу оплаты Paymos и оплачивает счёт любым токеном и в любой сети, включённых в вашем проекте — Tron, Ethereum, BSC, Solana и других поддерживаемых сетях. Дальше заказ в OpenCart обновляется сам: им управляет подписанный вебхук, а не возврат браузера покупателя. Инвойс выставляется в валюте заказа, а курс фиксируется в момент оплаты.

Главная особенность, о которой стоит знать сразу: вы сами выбираете, какой именно из *ваших* статусов заказа соответствует каждому этапу оплаты. В модуле заданы значения по умолчанию, но все пять сопоставлений — это выпадающие списки из вашей собственной таблицы статусов, так что Paymos подстраивается под текущий порядок работы магазина, а не навязывает чужой.

## Требования

- OpenCart 4.0.2.0 или новее (на версиях 4.0.0.0–4.0.1.1 расширение не установится);
- PHP 8.0 или новее с расширениями `curl`, `hash`, `json` и `openssl`;
- адрес магазина (Store URL) по HTTPS, доступный из публичного интернета;
- аккаунт Paymos с уже открытым в дашборде проектом, на который должен работать этот магазин.

Paymos PHP SDK встроен прямо в архив — ставить зависимости через Composer не придётся. Строки админки и витрины переведены на английский, русский, немецкий, испанский, турецкий и упрощённый китайский.

## Установка и подключение

1. Скачайте последний релиз со страницы [GitHub Releases](https://github.com/paymos-labs/opencart/releases/latest).
2. Загрузите `paymos.ocmod.zip` в разделе **Extensions → Installer**.
3. Перейдите в **Extensions → Extensions**, выберите **Payments** и установите Paymos.
4. Откройте его настройки, а в дашборде Paymos откройте нужный проект — текущий проект привяжется автоматически.
5. Нажмите **Connect Paymos** в настройках модуля.
6. Подтвердите показанные URL магазина и текущий проект в Paymos.

**Не переименовывайте архив.** OpenCart создаёт каталог расширения из имени загруженного файла, а пространства имён всех контроллеров внутри привязаны к этому каталогу. Переименованный zip установится в папку, к которой ни один файл внутри не сможет обратиться, и модуль тихо не загрузится.

Архив релиза один на всех и не содержит никаких учётных данных: ни API-ключа, ни секрета, ни ID проекта, ни секрета вебхука, ни OAuth-токена, ни кода устройства. Пока не завершён шаг 6, модуль неактивен.

Одно подтверждение сразу настраивает Sandbox и Live. Для каждого окружения Paymos использует ваш единственный активный платёжный ключ (или создаёт новый, если его нет) и привязывает вебхук инвойсов к магазину. Уже существующий вебхук используется повторно только при точном совпадении URL, категории и проекта; другой вебхук на том же адресе останется нетронутым. Авторизация устройства служит только каналом разовой доставки: короткоживущий токен быстро истекает и удаляется, а вызовы Merchant API подписываются HMAC.

## Хранение секретов

Учётные данные и временное состояние устройства хранятся в настройках OpenCart в виде зашифрованного конверта AES-256-GCM с ключом на основе `config_encryption`. Сохранённые секреты не выводятся на страницу админки, и полей для ручного ввода нет — при сохранении формы зашифрованный конверт остаётся нетронутым. После ротации ключа или секрета вебхука просто подключите модуль заново.

## Настройки

| Параметр | За что отвечает |
|---|---|
| Status | Показывать ли способ оплаты при оформлении заказа |
| Mode | Sandbox (тестовый) или Live (рабочий) |
| Credentials | Только чтение — подключён ли магазин |
| Webhook URL | Только чтение — зарегистрирован автоматически, показан для проверки |
| Title | Название способа оплаты для покупателя |
| Button text | Текст кнопки перехода на страницу оплаты |
| Pending / Confirming / Paid / Failed / Cancelled status | Ваш статус заказа для каждого состояния платежа |
| Sort order | Позиция среди остальных способов оплаты |

Адрес вебхука, на который регистрируется OpenCart:

```text
https://your-store.example/index.php?route=extension/paymos/payment/paymos.callback
```

## Статусы заказов

OpenCart создаёт заказ как обычно, ставит ему ваш **Pending status** с записью *Awaiting Paymos payment* в истории и переводит покупателя на страницу оплаты Paymos. Дальше движением управляет вебхук.

| Состояние платежа | Используемый статус | По умолчанию в чистом OpenCart |
|---|---|---|
| Перевод виден в сети, идут подтверждения | Confirming status | Processing |
| Пришла часть суммы или подтверждённый перевод откатился из-за реорганизации цепи | Pending status | Pending |
| Инвойс оплачен или переплачен | Paid status | Complete |
| Недоплата после истечения срока | Failed status | Failed |
| Истёк срок или отменён | Cancelled status | Canceled |

Каждый переход добавляет в историю заказа строку с идентификатором инвойса Paymos, а при подтверждении в блокчейне запись об оплате получает хеш транзакции и ссылку на обозреватель блоков.

Два правила работают поверх этой таблицы. Как только заказ получил ваш Paid status, запоздавший или пришедший не по порядку вебхук его уже не откатит — устаревший статус попадёт в историю как заметка и будет проигнорирован. А если сумма в подтверждённом вебхуке больше не совпадает с заказом, заказ перейдёт в Confirming status с пометкой *needs manual review* вместо завершения: изменившуюся после создания инвойса сумму должен проверить человек, а не скрипт.

## Проверка в тестовом режиме (Sandbox)

1. Оставьте **Mode** в Sandbox, включите способ оплаты и оформите заказ на своей витрине.
2. Найдите этот инвойс в дашборде Paymos и запустите нужный сценарий — оплата, переплата, недоплата, отмена. В Sandbox по таймеру ничего не подтверждается.
3. Откройте вкладку истории заказа: все события должны лечь по порядку с выбранными вами статусами.
4. Переключите **Mode** на Live. Оба окружения настроились при первом подключении, дополнительно делать ничего не нужно.

У тестовых платежей в Sandbox нет реального блокчейна, поэтому хеш транзакции и ссылка на обозреватель в строке оплаты не появляются — так и задумано.

## Вебхуки и сверка

Каждая доставка приходит с заголовком `X-Webhook-Signature` в формате `t={timestamp},v1={hmac_hex}` — это HMAC-SHA256 по точным байтам тела запроса с проверкой за постоянное время и поддержкой обоих секретов во время ротации. Идентификаторы событий сохраняются, поэтому повторная доставка подтверждается, а не применяется к заказу второй раз.

Финальный вебхук никогда не принимается на веру по одной подписи: прежде чем менять статус заказа, расширение запрашивает инвойс напрямую из Merchant API и сверяет его с сохранённым снимком.

Сверка инвойсов здесь сделана кнопкой, а не cron-задачей. Кнопка **Reconcile Paymos orders** в верхней части страницы настроек берёт до 50 незакрытых инвойсов за последние 24 часа, запрашивает каждый по API, прогоняет через те же правила и защиты, заодно сверяет ожидающие возвраты и показывает число обновлённых записей. Нажимайте её после сбоев или если заказ выглядит зависшим.

## Возвраты

Расширение поддерживает нативные возвраты через Paymos Merchant API (`/v1/refunds`) в двух режимах с расчётом суммы на сервере: `full` (полный возврат по инвойсу) и `overpayment` (возврат переплаты по инвойсу `paid_over`). Средства отправляются новой исходящей транзакцией строго на проверенный адрес `first_sender`, записанный Paymos при оплате инвойса: вручную адрес кошелька не вводится, а произвольные частичные суммы не поддерживаются.

Чтобы создать или проверить возврат в OpenCart:

1. Откройте **Extensions → Extensions → Payments → Paymos** в админке OpenCart.
2. Введите ID заказа OpenCart в панели **Paymos refunds** (`refundPanel`), чтобы увидеть доступные к возврату суммы, проверенный адрес `first_sender` и список операций.
3. Выберите действие возврата `full` или `overpayment` (`extension/paymos/payment/paymos.refund`).

При установке или открытии настроек регистрируется ежеминутная задача cron OpenCart (`paymos_refunds` → `extension/paymos/payment/paymos.refundCron`), а подписанные вебхуки и кнопка **Reconcile Paymos orders** также обновляют незавершённые возвраты. Завершённые возвраты попадают в историю заказа OpenCart после подтверждения через Merchant API. В режиме Sandbox можно симулировать финальные статусы возврата (`completed`, `failed`, `cancelled`).

## Решение проблем

**Paymos не остаётся установленным.** На магазине стоит OpenCart версии ниже 4.0.2.0. Расширение само удаляется, не создаёт таблиц и пишет в журнал ошибок OpenCart строку `[Paymos] Installation refused` с найденной версией. Обновите OpenCart и установите Paymos снова.

**Подключение пишет, что магазин должен работать по HTTPS.** У свежеустановленного OpenCart адрес магазина может быть пустым — тогда берётся URL каталога. Если там всё ещё HTTP, подключение отклоняется, чтобы не оставлять настройку в полусобранном состоянии. В сообщении указан найденный адрес — пропишите его HTTPS-версию в `config.php` OpenCart и повторите попытку.

**Заказ навсегда остаётся в Pending.** Запросите адрес вебхука выше из внешней сети: он должен отвечать без HTTP-авторизации и без редиректов, потому что редиректы не обрабатываются. Затем посмотрите строки `[Paymos]` в журнале ошибок OpenCart.

**При оформлении появляется ошибка "Paymos is temporarily unavailable".** Не удалось создать инвойс. Точная причина записана в логе; чаще всего это недоподключённое окружение или валюта заказа, с которой не работает проект.

**Заказ требует ручной проверки.** Его сумма изменилась между созданием инвойса и поступлением оплаты. В заметке истории сохранены обе цифры — закройте заказ вручную.
